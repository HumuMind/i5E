# 0005 样式作为字段：让还原出的页面像源页

状态：已定 · 2026-10-20 · 补充 [0001](0001-content-model.md)

## 背景

[0001](0001-content-model.md) 决定丢弃 class/style/颜色/字号，只留语义结构。代价现在能看见：7187 页里 3614 页（50%）没有页内层次，怪物页的红色大标题退化成一行粗体，属性区散成普通段落。

要求改成：还原出来的页面要尽量像源页。

## 选项

- **A. 保留完整 `style` 字符串。** 最像，但等于在原生应用里实现 CSS 级联，且 46 万处 `mso-*` 会漏进 UI。
- **B. 归一成有限字段。** 颜色、字号、字体族、对齐、缩进，加页级默认值。
- **C. 不放宽数据，只靠排版映射。** 最省，但那 50% 的页面永远平。

## 决定

采用 **B**（2026-10-20）。字段：

| 层级 | 字段 | 取值 |
|---|---|---|
| run | `c` | 颜色 `#rrggbb` |
| run | `sz` | 字号，磅（pt） |
| run | `fa` | 字体族：`song` `hei` `kai` `fang` `sans` `times` `mono` |
| 块 | `al` | 对齐：`c` `r` `j` |
| 块 | `ind` | 缩进，em |
| 页 | `style` | 页级默认值：占 60% 以上的取值提到页级，run 只留差异 |
| 页 | `css` | 外部样式表依赖，如 `../../style.css` |

字体族只保留 7 类。源里有几十种字体名、197 种 class，全部保留既无用也不可移植——iPad 上真正需要区分的是"衬线/黑体/楷体"这一档。

渲染侧分两个模式：`faithful` 用于对照与调试（连原文样式表一起套），`reading` 用于阅读（我们的字号、行宽、行高）。**数据保真，排版仍是产品决策。**

## 实测

| 项 | 前 | 后 |
|---|---|---|
| `content.jsonl` | 49.8 MB | 55.4 MB |
| gzip 后 | 12.1 MB | 12.2 MB |
| C1/C2/C4/C5/C6 | 通过 | 通过 |

体积涨 11%，压缩后只涨 1%——因为同页的样式高度重复，压缩能吃掉。

2943 页引用了外部样式表，994 页有页级默认样式。

视觉对照：怪物页（Word 内联样式）与法术页（依赖 `style.css`）都能还原到接近源页——标题的暗红、22pt 黑体、正文 8pt 宋体、`style.css` 的紫色 h4 都回来了。

## 后果

- 颜色与字号只是数据，不绑定排版决策；哪天要在 iPad 上放大字号，不影响数据层。
- `faithful` 模式依赖原文样式表，属于"对照工具"，不进正常阅读路径。
- **类名依然没保留**，所以 `style.css` 里 `.stat-block`、`table.basic`、`div.center` 这类基于 class 的规则用不上。这是下一个可补的字段。

## 重审条件

如果 `faithful` 需要在 iOS 上和浏览器像素级一致，说明字段还不够——那时候要么补 class，要么直接嵌 CSS，代价另算。
