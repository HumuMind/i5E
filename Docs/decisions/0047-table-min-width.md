# 0047 表格列宽：按实测的不可断词定下限

状态：已定 · 2026-10-26

## 问题

速查表里 `PHB24` 被折成 `PHB2` / `4`——这是中文排版里最难看的断行之一（拉丁词从中间断开）。

原因是列宽按"半角字符 = 半个字号"估算，而拉丁大写字母实际比这个宽约 15%，估算值不够。

## 决定

1. 每列计算**最长不可断片段**（连续的非空白 ASCII，如 `PHB24`、`1d6+2`）的**实际渲染宽度**（CoreText `CTLineGetTypographicBounds`）。
2. 列宽下限取这个实测值；自然宽度与压缩后的宽度都不能低于它。
3. 中文可以逐字断，所以中文内容的下限仍然是"一个字"。

## 为什么不用估算

估算值对中文够用（每字正好 1em），对拉丁字母系统性偏低。用 CoreText 实测只多几百次调用，而表格本来就只在需要时才排版。

## 效果

速查表的「来源」列不再折行，`PHB24`、`DMG24`、`XGE` 都完整显示。

## 遗留

`1d10 挥砍` 这类"数字 + 中文"的单元格仍会在数字后换行——那是合法的中文断行位置，不算问题。
