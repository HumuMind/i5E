# 0014 搜索结果：按页列出，跳到命中处并高亮

状态：已定 · 2026-10-21

## 背景

I7。搜索已经能用（FTS 召回 → 正文校验 → 够数即停），但结果只有一个页面标题，点开落在页首。

## 事实

| 项 | 值 |
|---|---|
| 页正文长度中位 | 1,025 字（比一屏还短）|
| p90 / p99 / 最大 | 3,193 / 10,162 / 98,475 |
| 超过 3,000 字的页 | 801 / 7,187 |
| 典型查询命中页数 | 巨龙 418、先攻 1,160、火球 202 |

九成页面不到一屏，所以"结果是页"在多数情况下够用；但 801 页超过 3,000 字，点开落在开头等于让用户自己找。

## 决定

- **结果按页列出**，按书内顺序（`detail=none` 拿不到词频，没有相关度可排）。
- 每条显示：章节标题、命中摘要、来源路径。
- **点开滚动到首处命中，并高亮该页全部命中。**
- 结果上限 80 条。

## 实现要点

`SearchHit` 增加 `blockIndex`；`PageText` 拆出 `leaves()` 与 `blockIndex(forOffset:)`，把整页正文里的字符偏移映射回顶层 block——注意 `PageText.of()` 的拼接方式不能变，否则跨语言正文哈希（`text_sha256`）会失配。

高亮要实现两遍：SwiftUI 的 `AttributedString`（标题、列表、表格）和 UIKit 的 `NSAttributedString`（两端对齐的正文段落）。

## 补记（2026-10-26）：排序与最短查询

原文只定了"按页列出、跳到首处命中"，没定排序——实际结果是按页序返回，搜「火球」先出「烈焰人」。
现已加入标题索引与两段检索，标题命中优先，见 [0041](0041-search-ranking.md)。

同时限制最短查询为 2 个字：单个汉字会命中几乎全库。

## 后果

- 搜索结果与阅读位置绑定，长页也能直达。
- 高亮依赖查询词原文匹配（大小写不敏感），不做分词级高亮——搜"火球"不会高亮"火球术"以外的同义词。
- 排序是文档顺序，不是相关度。这是 0007 的已知取舍，用户可能觉得"搜出来的第一条不一定是想要的"。

## 重审条件

如果用户抱怨排序，需要换 `detail=full` 让 bm25 可用，索引会从 28 MB 涨到 68 MB。
