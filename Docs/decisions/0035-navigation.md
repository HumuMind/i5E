# 0035 导航：全屏内容 + 浮动按钮 + 抽屉目录

状态：已定 · 2026-10-23 · 取代 [0013](0013-toc-sections.md) 里"用分栏承载目录"的形态（分组规则不变）

## 背景

原来用 `NavigationSplitView`：左侧目录、右侧阅读。iPad 与 Mac 上正常，但在 iPhone 上折叠成栈后，点目录项只会改变 detail 的内容，界面不会切过去——看起来像"点了没反应"。

## 决定

**取消分栏，三端统一为：全屏内容 + 浮动按钮 + 左侧抽屉。**

| 位置 | 内容 | 行为 |
|---|---|---|
| 左上 | ☰ | 打开抽屉；有历史时它左边还会出现 ← 返回 |
| 右上 | 🔖 书签 | 标记当前位置，图标随状态变化 |
| 右上 | ⚙ 设置 | 打开设置页 |
| 左侧抽屉 | 搜索框 + 书签区 + 目录分组 | 覆盖内容，点空白处或再点 ☰ 关闭 |

细节：

- 按钮是 40pt 圆形、`.regularMaterial` 背景，浮在内容之上；抽屉打开时整体隐藏。
- 抽屉宽度 `min(360, 屏宽 × 88%)`；背景铺到状态栏，内容留在安全区内。
- 阅读页顶部让出 44–48pt，避免第一行被按钮压住。
- 系统导航栏在两端都隐藏（iOS 用 `.navigationBar`，macOS 用 `.windowToolbar`），标题改由抽屉与章节路径承担。

## 为什么这样更好

1. **不再需要按 size class 分叉**：iPad、iPhone、Mac 走同一套结构，少一整类分支。
2. **阅读区更完整**：内容占满屏幕，没有常驻侧栏挤压版心。
3. **iPhone 上行为正确**：抽屉就是普通浮层，不存在"split 折叠后不跳转"的问题。

## 顺带修掉的一个排版问题

源页里存在真实的换行符，例如 `…边长不大于20 \n尺的…`。之前原样保留，渲染时被当成硬换行，出现"20"单独一行。

现在 `clean_text()` 把普通空白折叠成单个空格；`\u2028`（由 `<BR>` 生成）仍然保留，那是源页有意的换行。

C1 文本守恒与 C5 往返保真在改动后都通过。

## 调试参数

为截图与排查加了两个启动参数（走 UserDefaults 参数域，不影响正常启动）：

- `-openPage "<语料路径>"`：直接打开某一页
- `-openDrawer 1`：启动即打开抽屉
