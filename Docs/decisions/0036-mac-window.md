# 0036 Mac 窗口、快捷键与菜单

状态：已定 · 2026-10-26

## 决定

1. **单窗口。** 去掉「新建窗口」，`Cmd+N` 不再可用。
2. **快捷键**：

| 快捷键 | 动作 |
|---|---|
| `Cmd+F` | 打开查找面板并聚焦搜索框 |
| `Cmd+↑` / `Cmd+↓` | 上一页 / 下一页（按目录顺序）|
| `Cmd+B` | 添加或移除书签 |
| `Cmd+=` / `Cmd+-` | 放大 / 缩小字号 |
| `Cmd+,` | 设置 |
| `Esc` | 关闭查找 / 设置浮层（`完成` 绑的就是 `cancelAction`）|

3. **菜单**：
   - 应用菜单里放「设置…」（替换系统默认的偏好设置项）。
   - 新增「阅读」菜单，容纳上面除设置外的命令。
   - **目录不进菜单**——目录有 8,773 个节点，放进菜单既排不下也没法用。Mac 上它是左侧的常驻列（[0050](0050-mac-sidebar.md)），不需要菜单入口。

## 补记 · 2026-10-27：单窗口由场景清单强制

菜单里去掉「新建窗口」只是去掉入口，场景本身仍允许多窗口（iPad 上更明显）。
现在由 `Config/Info.plist` 的 `UIApplicationSupportsMultipleScenes = false` 关掉，
iPad 同时声明全屏、不做分屏——见 [0052](0052-window-and-size.md)。

## 为什么单窗口

现在 `WindowGroup` 允许多窗口，但所有窗口共享同一个 `AppModel`，会同时显示同一页。要支持多窗口得给每个窗口独立状态（各自的内容库连接、滚动位置、历史栈），成本明显高于收益。

阅读器一次看一页就够了；真需要对照时，iPad 分屏比 Mac 多窗口更自然。

## 实现要点

- **抽屉与设置的开关状态移进了 `AppModel`**。菜单命令在 Scene 层，拿不到视图里的 `@State`；把它们放到模型里，菜单与按钮共用同一份状态。Mac 上目录不在抽屉里（[0050](0050-mac-sidebar.md)），`showDrawer` 对它是空转。
- **搜索聚焦**用一个自增的 `searchFocusToken`：命令把它 +1，抽屉里的搜索框监听变化后取焦点。比传 binding 简单，也不会在抽屉未打开时误触发。
- **翻页按目录顺序**（`orderedPaths`，在启动时随目录树一起摊平），不是按滚动位置。
- `Esc` 只在 macOS 有效；它不关目录（Mac 没有抽屉），只是触发浮层"完成"按钮的 `cancelAction`。

## 后果

- Mac 上「设置」出现在应用菜单，符合系统习惯；同时工具栏的齿轮仍在，两条路都能到。
- 快捷键只在 macOS 生效（`CommandMenu` 在 iOS 上被忽略），iPhone 上没有副作用。
