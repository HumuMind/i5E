# 0034 TestFlight 与反馈：个人阶段不启用

状态：待定 · 2026-10-21（前置条件未满足）

## 结论

**现在不启用 TestFlight。** 测试者只有开发者本人时，TestFlight 没有意义——它解决的是"把包发给别人"的问题。

个人验证走 Xcode 直接装：

| 设备 | 方式 | 有效期 |
|---|---|---|
| Mac | 直接运行 | 无限制 |
| iPad / iPhone | Xcode + 自己的 Apple ID（免费开发者）| 7 天，到期重装 |

上真机需要一次性的设备信任步骤；免费账号的 7 天限制对开发阶段够用。

## 计划（有测试者时启用）

| 项 | 决定 |
|---|---|
| 渠道 | TestFlight **外部测试 + 公开链接**（内部测试需要 App Store Connect 成员，单人无意义）|
| 范围 | 先小范围邀请（朋友、跑团群），稳定后再公开链接 |
| 反馈 | TestFlight 内置（随手报问题）+ GitHub issue（需要讨论的改动）|
| 节奏 | **不按固定周期**，上游有实质更新时发构建。固定周期会产生大量"只改一句话"的构建，测试者也会疲劳 |

## 为什么现在不建远程仓库

开发者本人的判断：当前没有协作需求，仓库留在本地更简单。

代价是下面这些暂时没有落点，等真要发布时再一起补：

- issue 模板（I37）
- 支持 URL 与隐私政策 URL（App Store Connect 必填）
- TestFlight 的反馈出口

**注意**：App Store 上架时"支持 URL"是必填项，届时无论如何都要有一个公开地址——可以是一个单页的 GitHub Pages，不一定是完整仓库。
