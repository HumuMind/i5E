# 0025 分发与许可：目标 App Store，代码改 MIT

状态：已定 · 2026-10-21

## 背景

D5。目标是把 App 发到 App Store，而 GPL 与 App Store 的分发条款有公认冲突（VLC 2011 年因此下架）。

## 事实

- 上游 `DND5e_chm/LICENSE` 是 **GPL-3.0**，位于仓库根目录，名义上覆盖整个仓库。
- 上游 README 没有任何额外的分发条款。
- 本项目此前没有 `LICENSE` 文件，README 写着"GPL-3.0，与上游一致"。
- 内容（文本、翻译、美术）的著作权属于 Wizards of the Coast 及相应译者，**上游无权以 GPL 授权内容本身**。

## 决定

1. **分开发布式**：代码与内容各自声明许可。
   - 代码（App、ContentKit、构建工具）：**MIT**，见 `LICENSE`。
   - 内容及其派生数据（`content.db`、图片）：沿用上游 **GPL-3.0** 声明；内容本身的著作权归原作者，本项目不主张、不销售。
   - 两者的关系写在 `NOTICE` 里。
2. **目标渠道是 App Store**，短期用 TestFlight 验证。
3. **不上架任何 GPL 代码**：本项目没有链接或复用上游的 Python 工具，只读取上游产出的 HTML。
4. 设置页展示许可信息，README 顶部徽标同步更新。

## 为什么是"分开授权"而不是"全部 GPL"

如果整个项目保持 GPL-3.0，App Store 的分发条款（DRM、设备限制）会与之冲突，等于自己把上架路堵死。

而代码确实是独立实现的：数据层是 Swift、构建工具是 Python 重写的，没有链接上游任何代码。内容则是另一回事——它不是我们写的，我们无权变更其授权条款，只能沿用上游的声明并尊重原始权利人。

把两件事混在一个许可证里，既会让代码无法上架，也会给内容套上一个我们无权给出的许可。

## 上架前必须完成

1. ~~补 `LICENSE` 与 `NOTICE`~~（已完成）
2. 确认二进制里没有上游代码（目前没有；将来若复用 `Generator/` 的脚本要重新评估）
3. **联系上游作者**，说明这是独立实现、只使用其内容产物，并确认其态度
4. 内容侧符合 WotC 的 Fan Content Policy：免费、非商业、署名、不主张权利

第 3、4 条不是代码问题，是这个项目能不能长期做下去的前提。

## 后果

- App Store 的 GPL 冲突在代码层面解除；内容层面仍属灰色地带，但性质从"链接 GPL 代码"降到"分发引用内容"，风险量级不同。
- 上游若未来变更许可，内容侧条款需要重新评估。
- README、NOTICE、设置页三处保持同一口径。
