# 0021 双版本：章节路径 + 旧版徽标

状态：已定 · 2026-10-21

## 背景

I14。2014 与 2024/2025 两套并存，同名条目大量重合。

## 事实

| 项 | 值 |
|---|---|
| 法术条目 | 2014 版 361 条，2024 版 391 条，**同名 id 重合 359 条** |
| 玩家手册 | 168 页 vs 218 页 |
| 怪物图鉴 | 344 页 vs 600 页 |
| 全库标题重复 | 845 组（含同书内部重名，不限于双版本）|

搜「火球」会得到两条标题完全相同的结果。

## 但大部分场景本来就没有歧义

| 场景 | 有歧义吗 |
|---|---|
| 目录 | 没有——「——旧版内容——」已经分节 |
| 交叉引用 | 没有——链接解析成具体路径，2014 的页面链到 2014 |
| 书签与进度 | 没有——存的是路径 |
| **搜索结果** | **有** |
| 实体页（未做）| 会有 |

所以真正要修的只有"结果列表里怎么区分"。

## 决定

1. **搜索结果显示章节路径**（`玩家手册2024 › 第七章：法术`），带上下文。
2. **旧版页面加「旧版」徽标**。
3. **不做版本筛选开关**——全收是 [0006](0006-scope.md) 的决定，默认藏起来反而让人以为内容缺失。
4. **交叉引用不动**。

## 版本判定不需要映射表

目录里的分隔节点被 [0013](0013-toc-sections.md) 变成了章节标题，所以「旧版内容」会出现在标题链的第一位。判定就是 `chain.first == "旧版内容"`。

上游以后调整旧版范围，只要目录跟着改，这里自动跟随，不需要维护「玩家手册 → 2014」这类硬编码。

## 后果

- 搜索结果的第三行从"文件路径"变成"章节路径"——对用户更有意义，也让两版自然区分开。
- 845 组标题重复里有一部分是同书内部重名（如「万象无常书」里两个「宿命之英雄」），章节路径同样能区分。
- 将来做实体索引（I15）时，实体主键必须是 `(id, 版本)` 而不是单纯的锚点 id——359 个法术在两版里 id 相同。
