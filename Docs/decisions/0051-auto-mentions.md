# 0051 自动链接：正文里提到的条目连到它自己

状态：已定 · 2026-10-27

## 背景

源页里的提及大多没有链接。一句「施法者可以准备火球术」只有作者手写过的地方能点，
其余都是死文字：读者得自己去目录里翻。全库现有 6,966 条链接，覆盖率远低于"提及"的实际数量。

## 事实（离线试扫，全库 7,187 页）

| 项 | 数量 |
|---|---|
| 页面标题 | 6,988 个（5,738 唯一），683 个重名 |
| 标题块（h） | 10,227 个，只有 2,741 个带 `id`，能当锚点 |
| 裸扫命中（别名 ≥3 字、排除 self） | 153,119 处 |
| 其中已在作者链接里 | 9,545 |
| 其中在表格里 | 22,308 |
| 跨 run 边界的命中 | 212（0.14%） |

高频别名几乎全是规则词/字段名：生命值 5,456、豁免检定 2,924、附赠动作 2,910、
攻击检定 2,491、黑暗视觉 2,328、护甲等级 1,703。它们是数据块里的标签，不指名任何页面。
另有 1,846 个别名指向多个页面（`魔法物品` 49 个、`珍稀` 42 个、`火球术` 2 个版本）。

## 决定

**在构建期给正文补链接**：新模块 `Tools/content/mentions.py`，在解析完所有页、跑检查之前执行。
App 端只加"轻下划线 + 开关"，解析与跳转沿用 [0018](0018-cross-references.md)。

规则：

1. **别名来源**：页面标题 + 带 `id` 的标题块。标题里的 `｜English` 拆成两个别名。
2. **可用性**：中文 ≥3 字、必须含字母或数字（挡掉 `分隔符.htm` 这类纯符号标题）。
   英文别名要整词匹配，且得是"中文名后面的英文名"——前面是中文或行首、后面不接另一个英文单词，
   否则 `Dawn Carlos` 会把 `Dawn` 链到晨光术、`Doomsday` 会把 `Doom` 链到末日术。
3. **三档密度**：按别名出现在多少个页面，给它一个"最早出现的档位"——
   ≤50 页是「精简」，≤1000 页是「标准」，其余是「详细」。运行时按用户选的档位筛，
   所以一份内容库能同时支持四档（关闭 / 精简 / 标准 / 详细）。
4. **歧义消解**：唯一目标 → 用它；同书唯一 → 用它；2024 版唯一 → 用它；否则不链（宁缺勿错）。
   同一目标在一页里被提到几次就链几次：读者点哪一处都应该跳得过去，所以每处都带下划线。
5. **两字词**：只认带 `id` 的标题块（倒地、麻痹、借机攻击这类状态/术语），页面标题里的两字词
   （一环、人类、附录）太泛，不进索引。
6. **跳过** self、已有 `href`、`pre`、表格（表格里作者链接已足够，速查表再链会失控）。
7. **数据形态**：命中处拆 run，加 `href`（`路径#锚点`）与 `m: 1…3`。
   `m` 是详细档位（App 用 `m <= 当前档位` 决定能不能点、画不画线）；C5 往返用 `data-mention` 属性保留它。
8. **样式**：自动链接不换成链接蓝，正文色 + 低透明度下划线；设置里「自动链接」四档可选。
9. **名单**：`mention-deny.txt` / `mention-allow.txt` 各一行一个，`#` 注释。
   deny 用来日后砍掉误链，allow 用来强链想链的通用词——两者都不改代码。

## 预期规模

按上述规则实跑：**330,141 条**候选链接（精简 35,028 / 标准 108,044 / 详细 187,069），
覆盖 6,935 页（共 7,187 页）。

相对现有的 6,966 条源链接，"标准"约 15 倍。内容库 35.2 → 37.7 MB，构建耗时 +8 秒左右。
所有档位的链接都写进同一份内容库，切换档位不重新生成。

## 为什么放在构建期

- App 侧已经能解析「路径#锚点」（0018），补 `href` 即可，跳转、压栈、返回都不用改。
- 标题与锚点是跨页知识，运行时要每次启动扫全库；构建期只算一遍（实测 trie 全扫 4 秒）。
- 只改 `href`、不动文字，C1 文本守恒不受影响；规则错了改名单重跑 35 秒即可回滚。

## 已知的残留误链

中文没有词边界，别名是更长词的前缀时仍会误伤：`水元素` 会命中 `水元素裔`。这类只能靠
`mention-deny.txt` 逐个处理，或者等以后引入分词。英文那侧已经用整词 + 上下文规则压到
一千条左右，剩下主要是 `Gift of Theatre` 这种把曲名/称号里的词当成法术名的情况。

## 后果

- 正文会明显变"维基"。接受这个密度，用轻下划线压低视觉噪音；四档详细程度兜底。
- 每处提及都能点、都带淡下划线；嫌密就调到"精简"或关掉。
- 表格里的提及不链；速查页仍以作者手写的链接为准。
- 大量标题块没有 `id`（7,486 个），指向它们的提及只能落到页首——这是上游数据缺口，
  后续可考虑在管道里给标题补稳定 id。

## 重审条件

- 若读者反馈"链接太密/误链太多"，先调频率阈值与 deny 名单，再考虑只链专有名词。
- 若开关关掉后仍觉得页面花，说明问题在样式而不是链接数量。

## 补记 · 2026-11-03：下划线可配置

设置里新增二级页「跳转 → 下划线样式」：颜色（拾色器，支持透明度）、粗细（标准 / 粗）、恢复默认。

- 默认仍是 `theme.link.opacity(0.6)` + 细线，视觉上保持克制。
- 配置存 `ReaderState.mentionUnderlineColor` / `mentionUnderlineThick`，旧存档没有这两个字段时按默认。
- macOS 正文从 SwiftUI `Text` 换成 `NSTextView`（对应 iOS 的 `UITextView`），才能同时控制 underlineColor 和 `NSUnderlineStyle.thick`；
  链接点击、选中复制和 Cmd+点击开新 tab 仍走原来的 `handleLink`。
- 标题、列表、表格仍是 SwiftUI `Text`：颜色能改（`Text.LineStyle`），粗细改不了，保持默认细线。
