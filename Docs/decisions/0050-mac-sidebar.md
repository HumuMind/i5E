# 0050 Mac 常驻目录列

状态：已定 · 2026-10-27 · 取代 [0035](0035-navigation.md) 在 Mac 一端的抽屉

## 背景

0035 把三端统一成"全屏内容 + 浮动按钮 + 抽屉"。这在 iPhone 上是对的，但 Mac 的窗口默认就有 1100pt 宽，
目录却要按一下才出来：翻一章是"开抽屉 → 点条目 → 关抽屉"三步，而且抽屉会盖住正文。
窗口够宽的时候，把最常用的导航藏起来没有收益。

## 决定

**Mac 上目录常驻左侧：没有"目录"按钮，也没有抽屉。iPhone 与 iPad 保持 0035 不变。**

| 项 | iPhone / iPad | Mac |
|---|---|---|
| 目录 | 抽屉，按 ☰ 开合 | 常驻左列，宽 300pt |
| 左上角按钮 | ☰ 目录 | 只有 🔍 搜索 |
| 返回 / 书签 / 设置 | 浮动按钮 | 同左 |
| 查找与设置 | 居中浮层 | 居中浮层（盖住整窗） |

细节：

- 目录列与抽屉共用同一份内容（书签 + 六组目录）和同一个表头，只是去掉遮罩与滑入动画；
  两栏之间一条 1pt 分隔线，底色取主题的 `surface`，深浅色都跟随阅读主题。
- 窗口最小 720×480：目录 300 + 正文 420，再窄就压到 720pt 版心了。
- `showDrawer` 在 Mac 上没有意义：选条目、`Cmd+F` 都不该"关"任何东西，
  收抽屉统一走 `AppModel.closeDrawer()`（只有 iOS 真的改状态）。
- 占位文案按平台分叉：Mac 上是"在左侧目录里选一页开始读"。

## 为什么不用可拖动的分栏

SwiftUI 里能做可拖动侧栏的是 `NavigationSplitView`，但 0035 已经因为"iPhone 折叠成栈后点目录不跳转"
弃用它，重新引入等于同时维护两套导航结构。固定 300pt 已经放得下四级缩进的目录标题，
省掉拖动状态、栏宽记忆和一套额外的手势。

## 后果

- Mac 上翻目录从三次操作降到一次，且翻的时候正文不被遮住。
- 目录列的展开状态沿用 `ReaderState` 的展开/折叠记录，与 iPad 抽屉共享同一份记忆。
- 侧栏会跟随当前页滚动（[0038](0038-state-and-search.md) 补记）：跳转、翻页、启动恢复之后，
  目录自动滚到当前条目；抽屉与常驻列共用同一个 `TOCTree`，两端行为一致。
