# 0020 速查页：卡片瀑布流 + 原版表格开关

状态：已定 · 2026-10-21

## 背景

I13。有一批页面本质是数据表（法术总表、物品总表、怪物总表），当普通文档读很别扭。

## 先纠正一个数字

此前记录里的「2,603 个速查页」是错的。那个数字来自文件里的 `WinCHM` 标记——WinCHM 是上游用的**编辑器**，不是内容类型，这 2,600 页分布在所有书里（多元宇宙的怪物 283 页、模组 249 页……）。

真正的速查内容：

| 口径 | 数量 |
|---|---|
| `速查/` 目录下的页 | 34（其中 21 个是纯链接索引）|
| 全库单表 ≥50 行 | **88** |
| 表格为主（正文 <800 字、表 ≥10 行）| 143 |

最大的几张：970×11（5E万法大全）、711×7、672×6、529×7、497×7。列数集中在 6–11。

## 决定

1. **判据**：页面里行数最多的一张表 ≥50 行 → 视为速查页，换专用视图。低于这个量级仍留在文档流里。
2. **默认视图：卡片瀑布流。** 每条记录一张卡片：首列作标题（带链接则显示为链接色、可点），其余列按「表头：值」列出。用 `LazyVGrid` 自适应列数，iPad 上 2–3 列，iPhone 上单列。
3. **筛选：文本 + 分面。** 文本匹配所有单元格；列的去重取值 ≤14 种时自动生成筛选菜单（稀有度、环阶、学派、来源这类），最多取 4 列做分面。名称列取值太多，不做分面。
4. **原版入口：界面内悬浮开关**（胶囊，右下角），在「卡片 / 原版」之间切换。原版是按内容估宽的表格，iPhone 上横向滚动。
5. **懒加载**：卡片用 `LazyVGrid`，原版表格行用 `LazyVStack`，970 行的表也不会一次性构建。

## 为什么保留原版

卡片是对数据的重新组织，可能丢失列之间的相对位置（比如某列表示层级缩进）。给一个"按原样看表格"的开关，用户需要对照时可以切回去，成本只是一个本地状态。

## 后果

- 88 个页面走新视图，其余 7,099 页不受影响。
- 分面是自动推断的，遇到语义特殊但取值少的列（比如「是否」）也会生成菜单，属于可接受的噪音。
- 卡片取前 6 个非空字段，超出的不显示——需要完整信息时切原版。

## 重审条件

如果发现某些表首列不是名称（比如宽表首列是序号），卡片标题会变成序号，需要按内容特征改判据。
