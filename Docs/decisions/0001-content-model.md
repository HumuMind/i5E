# 0001 内容模型：文档流打底，实体做标注层

状态：已定 · 2026-10-20 · 存储形态被 [0004](0004-source-archive.md) 取代，样式丢弃的决定被 [0005](0005-style-fields.md) 取代

## 背景

上游是 HTML，我们要渲染成原生页面。真正的问题不是"怎么把标签转过去"，而是**把内容切到多细**：切得粗，只能做全文搜索；切得细，才能做"按环阶筛法术""按挑战等级排怪物"这类索引。这个粒度决定了数据库 schema 和 UI 的上限，改一次要重跑全量。

## 事实

2026-10-20 对 `DND5e_chm/` 实测：

| 项 | 数值 |
|---|---|
| HTML 文件 | 7207 个 |
| 正文体积 | 102 MB（427 MB 总量里其余是图片、`.wcp`、备份） |
| 文件大小 | 中位 3 KB，均值 14 KB，最大 905 KB；>200 KB 的仅 47 个 |
| 来源族 | 手写 3174（44%）／WinCHM 速查 2603（36%）／Word 导出 1430（20%） |
| 带 `id` 锚点 | 1193 个文件 |

三个关键结论：

1. **条目级结构存在，但只在部分内容里规整。** 法术页非常规整——`<H4 id="Acid_Splash">酸液飞溅｜Acid Splash</H4>`，紧跟 `<EM>塑能 戏法（术士、法师）</EM>` 和一组 `<STRONG>施法时间：</STRONG>` 字段，2014 与 2024 两版同构。怪物页则是 Word 导出，单页 44 KB 里绝大部分是 `mso-*` 内联样式噪音。
2. **锚点可以白拿。** 已有 1193 个文件的 `id` 是英文规范名（`#Blade_Ward`），速查页已经在用 `<a href="玩家手册2024/法术详述/0环.htm#Blade_Ward">` 跳转。交叉引用不必重新设计 ID 体系。
3. **速查页是派生物。** 2603 个 WinCHM 页面以列表、索引、汇总表为主，内容是其他页面的二次组织。它们占文件数 36%，但不承载原始文本。

## 选项

- **A. 纯文档流。** 一个 HTML 文件 = 一个页面，切成 block 序列（标题／段落／列表／表格／图）。
  收益：覆盖 100%，最快出可用的阅读器，解析器只有一套。
  代价：目录和搜索只能到"段落"级。README 承诺的"索引"做不出来，法术没法按环阶筛，怪物没法按 CR 排。

- **B. 纯实体。** 先定义法术／怪物／NPC／物品／规则条款几类实体，逐类写解析器，其余丢弃或降级。
  收益：索引和筛选能力最强，速查页可以整个替代掉。
  代价：每个解析器都要跟着上游格式漂移维护；解析失败 = 那部分内容直接读不了。

- **C. 文档流打底 + 实体标注层。** 全量走通用 block 解析，产出"页 → block"；再在 block 上加实体标注（某段是法术条目、指纹是哪个字段）。解析器按类型逐个加，失败的自动退化成纯文档流。
  收益：任何书先能读，再逐个变好；解析失败只丢索引能力，不丢内容。
  代价：两套数据模型要同时维护，标注层需要"哪个 block 属于哪个实体"的边界规则。

## 决定

采用 **C**（2026-10-20）。全量内容解析为「页 → block」文档流，实体作为标注层叠加在同一份 block 数据上；实体解析失败时自动退化为纯文档流，不阻塞阅读。

理由：A 的天花板低于 README 已经写下的承诺；B 的失败模式是"整本书打不开"，对一个阅读器不可接受。C 把风险限制在"索引少一条"。

第一批实体**只做法术**，字段范围：中文名、英文名、锚点、环阶、学派、是否仪式、可用职业、施法时间、施法距离、法术成分、持续时间、升环段、正文。它是唯一已验证规整、覆盖多本书、且索引效果能被直接验证的类别。

怪物（Word 导出，1430 个文件）与物品**留到第二批**，解析成本高一个量级。

## 后果

- 需要一份稳定的 block schema，并接受它比 HTML 表达能力弱（复杂表格、浮动图要单独处理）。
- 实体标注规则会随上游更新漂移，必须有"解析失败不影响阅读"的降级路径。
- 2603 个速查页是否收录，变成一个独立问题（见 open-questions）。

## 重审条件

- 如果实测发现 90% 以上内容都能规整到实体级，可以直接收敛到 B。
- 如果 block schema 在实现中频繁需要打补丁，说明粒度选错了，回到本文件重议。
