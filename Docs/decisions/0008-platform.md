# 0008 平台与框架：SwiftUI，最低 iOS 26 / macOS 26

状态：已定 · 2026-10-20

## 背景

I1。数据侧已收口，要开始做 App。框架和三端策略决定后面所有代码的形态。

## 选项

- **SwiftUI + 多平台 target。** 一套 UI 代码跑 iPad/iPhone/Mac。
- **UIKit。** 排版控制力最强，但三端要各写一遍，单人维护不动。
- **SwiftUI + Catalyst。** 复用度高，但 Mac 上的窗口行为、菜单栏、滚动观感都不像原生应用。

## 决定

- **SwiftUI**，iPad / iPhone / Mac 共用一个 multiplatform target。
- **最低 iOS 26 / macOS 26**，不做 `if #available` 分支。
- **Mac 用原生 SwiftUI 窗口**，不用 Catalyst。

## 理由

只有一个人开发，没有测试矩阵。锁定一个系统版本能省掉大量分支判断，这个收益比"多覆盖两年设备"更实在。

按年号命名，26 是 2025 那一代；到 2026 年底它已经是"上一代"，等于当前 + 往前一代，只排除卡在两代以前不动的设备——这个策略本身是合理的。

Catalyst 被排除是因为 Mac 用户对窗口、菜单、滚动的预期和 iPad 完全不同，与其两头不讨好，不如写一次原生窗口。

## 代价

**明确记录一个代价：阅读器是少数"老设备还有用"的场景。** 很多旧 iPad 就是买来当电子书阅读器的，定 26 会把它们整批排除。这是有意接受的取舍，不是没想到。

## 重审条件

如果上线后发现主要目标用户里旧设备占比很高，降到 iOS 18 的成本主要是补若干可用性判断，不是重写。
