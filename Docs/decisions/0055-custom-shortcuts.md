# 0055 可配置快捷键

状态：已定 · 2026-11-03

## 背景

快捷键之前写死在 `commands` 的 `.keyboardShortcut` 里。用户问有没有快捷键，并要求设置里加一个二级页来配置。

## 决定

1. **只做 macOS**：设置 → 快捷键。iPad/iPhone 不提供配置页；外接键盘仍用默认值，以后需要再补。
2. **可配置 10 个键位 + 1 个点击修饰键**：后退、前进、搜索正文、上一页、下一页、添加或移除书签、放大字号、缩小字号、新建标签页、关闭标签页；以及“在新标签页打开链接”的点击修饰键。
3. **录制规则**：至少需要 ⌘/⌃/⌥；Esc 取消；不能与其他动作重复；⌘Q、⌘, 受保护，⌘W 只允许给"关闭标签页"（系统用它关窗口）。
4. 支持单项/全部恢复默认；存在 `ReaderState.shortcuts`，跨启动保留。
5. `Cmd+,` 与 `Esc` 保持系统/约定快捷键，不参与配置。

## 实现

- `KeyShortcut` 放在 ContentKit（Codable，不依赖 SwiftUI）；`ShortcutAction` 与默认值在 App。
- 菜单项优先用模型里的快捷键；设置改动后再用 AppKit 同步一遍 `NSMenuItem`（`MenuShortcuts.apply`）。
  SwiftUI `commands` 只在场景重建时重算，直接改菜单项的 keyEquivalent 最稳。
- 录制用 `NSEvent.addLocalMonitorForEvents`；录制期间 `isRecordingShortcut` 让全局的关闭标签页监听让路。
- 关闭标签页仍然保留本地监听：系统"关闭窗口"占着 ⌘W，菜单项会冲突。

## 后果

- 改快捷键即时生效，菜单上的显示也同步。
- 不能把某个动作设为"无快捷键"，只能改或恢复默认。
- 配置保存在本机 UserDefaults；以后若做 iCloud 同步要另外迁移。
- Mac 的菜单显示依赖 AppKit 同步层；以后改 SwiftUI 命令时要记得保留它。

## 补记 · 2026-11-03：链接的点击修饰键

Cmd+点击开新标签页也纳入快捷键页：标签页组里新增“在新标签页打开链接”，点开是一个
⌘/⌃/⌥/⇧ 的勾选面板，至少保留一个，默认 ⌘。

- 匹配要求修饰键**完全一致**：只选 ⌘ 时，⌘+⇧ 点击不会开新标签页。
- 存在同一个 `ReaderState.shortcuts` 里，key 用特殊值 `click`，不参与菜单键位同步。
- ⌘ 最稳；⌃ 可能被系统当成右键，⇧/⌥ 可能和文本选择手势冲突，面板里有提示。
