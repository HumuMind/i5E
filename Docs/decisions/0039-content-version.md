# 0039 内容版本对用户可见

状态：已定 · 2026-10-26

## 决定

设置页的「内容」区块显示四项：

| 项 | 示例 |
|---|---|
| 页面 | 7187 |
| 上游版本 | `81b587c51 · 2026-10-15` |
| 提交 | 1015之存一下 |
| 应用版本 | 0.1.0 (39) |

数据来自 `content.db` 的 `meta.build` 字段（构建期写入），不解码任何新格式。

## 为什么值得占四行

内容出问题时，"你是哪个版本"是第一个要问的问题。上游每周更新两三次，同一个法术在不同 commit 里可能已经改过。

把上游 commit 短哈希和日期摆在设置里，用户反馈时截个图就能定位——不需要我们再去猜他装的是哪个包。

## 为什么不做「复制版本信息」

[0037](0037-no-sharing.md) 定了不做复制功能。为保持口径一致，这里也不加拷贝按钮。

如果将来反馈量大到需要结构化信息，再考虑——那时更应该做的是崩溃/诊断上报，而不是让用户手动复制。
