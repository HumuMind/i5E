# 0018 交叉引用：点击压栈、锚点定位

状态：已定 · 2026-10-21 · 修改 [0011](0011-typography.md) 里"正文用 UILabel 渲染"的实现方式

## 背景

I11。正文里有 6,966 条链接，此前全部是死文字。

## 事实

| 类型 | 数量 | 占比 |
|---|---|---|
| 跨页带锚点 | 6,560 | 94% |
| 外部链接 | 200 | 3% |
| 目标缺失 | 100 | 1.4% |
| 本页锚点 | 74 | 1% |
| 跨页无锚点 | 32 | 0.5% |

典型形态是速查表里的法术名，链到法术详述页里的 `<H4 id="Fireball">`。所以这题的核心是"跨页 + 锚点"，不是普通的网页跳转。

## 决定

1. **构建期解析链接**。`href` 统一改写成「语料内路径#锚点」；外部链接原样保留；解析不到的**去掉 href、保留文字**。与图片（[0016](0016-images.md)）同一套思路——App 里不做路径推导。
2. **点击压栈**。点链接压入目标页，支持返回按钮与右滑返回。（2026-10-27 起不再用 `NavigationStack`，
   改为自己管历史与位置，见文末补记。）
3. **锚点定位**。扫目标页的 block：标题看 `id`，普通块看 `anchors`，得到顶层 block 序号后滚过去。
4. **外部链接交给系统浏览器**。

## 实现要点

**正文从 UILabel 换成 UITextView。** `UILabel` 不能响应链接点击，这是 0011 定"两端对齐用 UILabel"时没考虑到的。改用 `UITextView`（`isEditable = false`、`isScrollEnabled = false`、`textContainerInset = .zero`），在 `textView(_:shouldInteractWith:)` 里拦截。

标题、列表、表格里的链接走 SwiftUI `Text` 的 `.link` 属性，用 `OpenURLAction` 拦截。

## 后果

- 链接只在构建期解析一次，上游改文件名后重新构建即可，App 无需知道路径规则。
- 本次丢弃 172 条失效链接，它们退化成普通文字，不会出现"点了没反应"。
- **本页锚点也走压栈**（同页再压一层），返回栈会多一层。这类只有 74 条，暂时不优化。
- C3 里 `lost_ids` 过滤掉了 `winchm_template_*`——那是 CHM 模板按钮的锚点，不是正文锚点。

## 补记：中文路径被 URL 编码，导致点卡片一直转圈

速查卡片点法术名后页面一直加载中。原因是内部链接经 `URL(string:)` 之后，
`relativeString` 返回的是百分号编码（`%E7%8E%A9...`），拿它去查内容库自然查不到。

修法：不要从 `URL` 反拆字符串，用 `url.path`（已解码）+ `url.fragment`。
新增 `Page.splitURL`，并用两个单测锁住中文路径与纯锚点两种形态。

同时给页面加载加了失败态——查不到页时显示"这一页打不开"，而不是无限转圈。
无限转圈会把"数据有问题"伪装成"还在加载"，是最难排查的一种表现。

## 补记 · 2026-10-27：去掉 NavigationStack，返回时复位

链接变多之后，系统那套转场开始碍事：

- **不要转场动画**。`NavigationStack` 的 push/pop 动画关不掉，而翻书要的是"咔"一下换页。
  三端改成同一个容器：只渲染栈顶的 `PageScreen`，用 `navigationToken` 换 id 强制重建。
  代价是 iOS 上没有了系统右滑返回手势，返回走浮动条上的按钮。
- **返回要回原位**。新增 `routeOffsets`，与 `routes` 等长：前进前记下当前页的滚动位置，
  返回时 `PageScreen` 用栈顶那一层的偏移做初始落位。
- 顺带把滚动位置上报从 500ms 防抖改成**立即上报**（写 UserDefaults 仍然防抖）——
  否则刚滚完就点链接，记下的是半秒前的旧位置。
- **转场**：前进从右侧滑入 40pt 并淡入，返回从左侧；旧页只淡出，不跟着滑。
  目标页在入栈**之前**先读进内存（`show()` 里预读）：如果内容在动画中途才出现，
  SwiftUI 会把这次插入识别成普通更新，动画直接跳到终态——看起来就是"炒一下"。
- **减弱动态效果**：系统开了 Reduce Motion 就不做转场，直接换页。
- **定位完成前不画正文**。有缓存页时，目标 block 在 `PageScreen.init` 里就算好；
  `ReaderView` 先以 0 透明度等一帧、滚到位再显示。不这样做就会"先露一眼页首，再跳到目标"。
  最近 30 页留在内存里，返回时第一帧就有内容可用。

## 重审条件

- 如果同页锚点的返回体验确实别扭，改成"原地滚动"而不是压栈。
- 如果上游出现大量跨页无锚点链接，需要考虑目标页的视觉提示（比如顶部闪烁）。
