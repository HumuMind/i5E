# 0018 交叉引用：点击压栈、锚点定位

状态：已定 · 2026-10-21 · 修改 [0011](0011-typography.md) 里"正文用 UILabel 渲染"的实现方式

## 背景

I11。正文里有 6,966 条链接，此前全部是死文字。

## 事实

| 类型 | 数量 | 占比 |
|---|---|---|
| 跨页带锚点 | 6,560 | 94% |
| 外部链接 | 200 | 3% |
| 目标缺失 | 100 | 1.4% |
| 本页锚点 | 74 | 1% |
| 跨页无锚点 | 32 | 0.5% |

典型形态是速查表里的法术名，链到法术详述页里的 `<H4 id="Fireball">`。所以这题的核心是"跨页 + 锚点"，不是普通的网页跳转。

## 决定

1. **构建期解析链接**。`href` 统一改写成「语料内路径#锚点」；外部链接原样保留；解析不到的**去掉 href、保留文字**。与图片（[0016](0016-images.md)）同一套思路——App 里不做路径推导。
2. **点击压栈**。详情列用 `NavigationStack`，点链接压入目标页，支持返回按钮与右滑返回。
3. **锚点定位**。扫目标页的 block：标题看 `id`，普通块看 `anchors`，得到顶层 block 序号后滚过去。
4. **外部链接交给系统浏览器**。

## 实现要点

**正文从 UILabel 换成 UITextView。** `UILabel` 不能响应链接点击，这是 0011 定"两端对齐用 UILabel"时没考虑到的。改用 `UITextView`（`isEditable = false`、`isScrollEnabled = false`、`textContainerInset = .zero`），在 `textView(_:shouldInteractWith:)` 里拦截。

标题、列表、表格里的链接走 SwiftUI `Text` 的 `.link` 属性，用 `OpenURLAction` 拦截。

## 后果

- 链接只在构建期解析一次，上游改文件名后重新构建即可，App 无需知道路径规则。
- 本次丢弃 172 条失效链接，它们退化成普通文字，不会出现"点了没反应"。
- **本页锚点也走压栈**（同页再压一层），返回栈会多一层。这类只有 74 条，暂时不优化。
- C3 里 `lost_ids` 过滤掉了 `winchm_template_*`——那是 CHM 模板按钮的锚点，不是正文锚点。

## 重审条件

- 如果同页锚点的返回体验确实别扭，改成"原地滚动"而不是压栈。
- 如果上游出现大量跨页无锚点链接，需要考虑目标页的视觉提示（比如顶部闪烁）。
