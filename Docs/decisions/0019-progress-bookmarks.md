# 0019 阅读进度与书签

状态：已定 · 2026-10-21

## 背景

I12。要回答三件事：位置怎么表示、存在哪、多设备要不要同步。

## 事实

| 项 | 值 |
|---|---|
| 每页顶层 block 数 | 中位 **5**，p90 23，最大 573 |
| 每页正文字数 | 中位 1,025 |
| 上游更新频率 | 近一个月 15 次提交 |
| 单次改动页数 | 通常 1–213 页（0.5%–3%）；有一次改名动了 966 页 |

页面很小——中位页只有 5 个块，所以"块序号"等同于半页精度；更新很频繁但每次只碰少数页。

## 决定

1. **位置 = 页面路径 + 正文字符偏移**（不是块序号，不是百分比）。
   字符偏移与字号无关，精度到段内；文本微调时偏移仍落在附近，退化是渐进的。
2. **存储用 UserDefaults**，外面包一层 `ReadingStore` 协议。
   数据量是几十条书签 + 一条最近位置，UserDefaults 足够；将来要换文件或 iCloud 只换实现。
3. **v1 不做多设备同步。**
4. **启动时自动回到上次阅读位置**（含页内偏移）。
5. **进度显示为章节路径**（`玩家手册2024 › 第一章 › 玩家还是DM？`），不显示页内百分比。

## 为什么自动恢复

这是个查阅型应用，但首页（`写在前面.html`）几乎没有信息量。相比之下，回到上次读到的位置更符合预期——尤其连续查同一个法术时。

## 内容更新后的兜底

书签额外存**段落开头约 20 字的快照**。上游有一次提交改名了 966 个文件，路径型书签会整批失效，所以：

- 路径找不到 → 标记失效，保留条目可手动删除
- 路径在、偏移漂了 → 用快照在该页里搜一次，命中就修正

字段已经预留，不需要事后改结构。

## 实现要点

- 滚动位置通过 `ScrollView` 的 `scrollPosition(id:)` 拿到顶部 block，再换算成字符偏移（`PageText.offset(ofBlock:)`）。
- 写盘做了去抖（滚动停止 500ms 后写）与最小变化阈值（80 字以内不写）。
- 章节路径在启动时由目录树摊平成 `页面路径 → 标题链`，O(1) 查询。

## 后果

- 书签与进度都是纯本地数据，删 App 即丢。
- 位置精度依赖正文未变；页内文字大改时可能偏几段，但不会跳到别的页。
