# 0053 正文可选中复制

状态：已定 · 2026-10-29

## 背景

[0037](0037-no-sharing.md) 定了"不做分享与复制"，重审条件写的是"用户明确要求把规则发到群里"。
现在用户明确要求内容可复制，用途是 DM 备团：把规则、法术和怪物数据贴到自己的笔记里。

## 决定

1. **阅读内容恢复系统选中**：正文、标题、列表、表格、速查页都可以长按选词、拖选并复制。
2. **仍不做**分享面板、导出（纯文本 / Markdown / PDF）和"整页复制"按钮；复制只走系统手势与剪贴板。
3. 目录、搜索、设置这些操作界面不参与选中——它们是控件，不是内容。

## 实现

- iOS 正文段落是 `UITextView`，改回 `isSelectable = true`；链接交给系统的文本项交互
  （`textView(_:primaryActionFor:defaultAction:)`），删掉 [0038](0038-state-and-search.md) 补记里的自定义点击命中。
  长按链接的菜单只保留"打开"与"复制文字"，避免默认的"打开链接"跳出 App。
- 标题、列表、表格、速查页这些 SwiftUI `Text`：在 `ReaderView` 与 `ReferenceView` 的内容区加
  `.textSelection(.enabled)`。
- 展示层不改数据：复制出来的是渲染后的文字，不带源页 HTML。

## 后果

- 长按正文会出现系统的选择手柄和编辑菜单；单击链接仍然跳转，不会进入选中状态。
- 复制出去的文字，著作权仍归原作者/译者。App 本身不提供分享与导出，与 [0025](0025-license-distribution.md) 一致。
- 一次只能选一个 `Text` 或一个正文段落：标题与段落之间做不到跨块连续选择，整页复制仍要逐段来。
  若"整页复制"成为高频需求，再单独评估一个动作，不要顺手把导出也做进来。
- 设置页的版本信息仍不加复制按钮，见 [0039](0039-content-version.md)。
