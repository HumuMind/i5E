# 0013 目录首屏：沿用上游自带的六个分组

状态：已定 · 2026-10-21

## 背景

I6。目录有 8773 个节点、81 个顶层，直接平铺到侧栏是没法用的。

## 事实

上游目录里本来就带着分隔节点（无子节点、标题是 `——核心规则——` 这种），正好把 81 个顶层切成六段：

| 分隔符 | 后面的内容 |
|---|---|
| ——核心规则—— | 玩家手册2024、城主指南2024、怪物图鉴2025 |
| ——规则扩展—— | 珊娜萨、塔莎、魔邓肯、费资本、毕格比、万象无常书、启封奥秘 |
| ——战役设定—— | 剑湾、艾伯伦、拉尼卡、荒洲、塞洛斯、鸦阁、龙枪…共 23 本 |
| ——旧版内容—— | 2014 版玩家手册 / 城主指南 / 怪物图鉴 / 瓦罗 / 魔邓肯旧版 |
| ——合作内容—— | 第三方 23 本 |
| ——其余杂项—— | UA、Drop、贤者谏言、英雄盛宴、电子资源、更新日志、鸣谢 |

另有 `补遗（未归类）` 与 `未收录于目录` 两个由合并过程生成的节点，不属于任何章节。

## 决定

- **直接用上游的分隔节点做章节**，不重新组织内容。
- 分隔符之前的内容（写在前面、本书速查）收成固定的「开始阅读」段。
- `补遗`、`未收录于目录` 放进末尾的「其他」段。
- 章节可折叠，展开后是书，再展开是章节。

首屏从 81 行变成 8 行。

## 后果

- 零重组成本；上游调整分组，我们自动跟随。
- 识别分隔符靠"无子节点 + 标题含全角破折号"，属于启发式。上游如果换写法（比如用空标题），分组会失效，需要回来改 `TOCSectionBuilder.isSeparator`。
- 分组标题会去掉首尾的破折号再显示，`————————` 这种无名分隔符会落到「其他」。

## 重审条件

如果上游改用真正的树层级表达分组（而不是分隔节点），这套启发式就该删掉，直接读层级。
