# 0023 可访问性：可调字号 + VoiceOver + 跟随系统偏好

状态：已定 · 2026-10-21

## 背景

I16。现排版是固定的 19pt，标题只是普通文本，表格逐格朗读没有上下文。

## 决定

1. **三档字号**（小 17 / 标准 19 / 大 22），在新增的设置页里切换，存入 UserDefaults。
   版心按 `720 × size / 19` 等比缩放，所以三档下每行都在 33–42 字之间——放大字号不会破坏行宽。
   表格字号按 19→16→13 的阶梯同时缩放，下限 12。
2. **不做完整 Dynamic Type**。版心、表格列宽、参考卡片网格全部按固定字号调过，跟随系统 7 档字号等于所有布局重算，而收益与"用户自己选一档"重叠。
3. **VoiceOver**：
   - 标题加 `.isHeader`
   - 表格每行合成一个元素，朗读「物品名：火球术，环阶：三环」
   - 参考卡片朗读「火球术，环阶：三环，学派：塑能」
   - 图片读 `alt`，没有则读「插图」
4. **跟随系统偏好**：`accessibilityReduceMotion` 为真时，滚动与模式切换的动画都关掉。

## 为什么是"档位"而不是"滑杆"

三档对应三种真实场景：视力正常、想省点眼力、需要明显放大。连续滑杆会让人反复调，而且每一档都要保证版心与表格仍然合理——三档可以逐档调好，滑杆不行。

## 设置页

放在阅读页工具栏，齿轮图标与书签并排。内容：

- 阅读字号（分段控件）
- 内容信息：页面数、版本号
- 一行说明：内容来源与纠错渠道

## 后果

- 字号变了，`ReadingMetrics` 通过 environment 下发，正文、标题、表格、参考卡片一起变；版心跟着缩放，不会出现"字大了但行宽没变"导致的每行字数暴涨。
- VoiceOver 的表格朗读是"每行一个元素"，行内不再逐格停——想逐格看可以关掉朗读或切到原版表格。
- 未处理的：图片没有有意义的 alt（上游数据里 alt 基本是空的），只能读"插图"。

## 重审条件

- 如果 App Store 审核对手势/朗读有具体要求，或收到低视力用户反馈字号仍不够，再评估 Dynamic Type。

## 补记：字号设置一开始不生效

设置页能改、也能持久化，但正文纹丝不动。原因是 `readingMetrics` 这个环境值
在 `ReaderView` / `ReferenceView` 里被"读出来又原样注回去"，而**根视图从来没有
把 `AppModel.metrics` 放进去**——于是整棵树永远拿到默认的 19pt。

修法：只在 `i5EApp` 注入一次，子视图只读不覆盖。另外给 `UITextView` 的
`updateUIView` 加了 `invalidateIntrinsicContentSize()`，否则字号变了、
UIKit 仍返回旧高度，SwiftUI 会沿用旧尺寸。

教训：环境值"读—写同名键"是个静默的错误模式——它不会崩，也不会警告，
只是安静地不生效。以后再引入环境值，注入点只应有一处。
