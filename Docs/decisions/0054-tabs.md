# 0054 多标签页：每页独立历史，Mac 放进工具栏

状态：已定 · 2026-10-29

## 背景

单窗口、单阅读位置，想对照两页只能来回跳（[0035](0035-navigation.md)）。
用户要求像浏览器一样开多个 tab 来回切，并问 tab 能不能和 Mac 的关闭/最小化/放大在同一行。

## 决定

1. **每个 tab 独立**：页面、返回/前进历史、滚动位置互不影响；切换 tab 时整页重建。
2. **新建 tab 复制当前页**：路径和当前位置，历史为空，用户再自己导航。
3. **关闭**：每个 tab 有 ×；只剩一个时不显示 ×，至少保留一个。
4. **Mac 放工具栏**：窗口用统一工具栏（`.windowToolbarStyle(.unified)`），tab 条放在 principal 位置，
   与红绿灯同一行；窗口标题去掉。`Cmd+T` 新建，`Cmd+W` 关闭当前 tab。（2026-10-29 改为正文列顶部，见补记）
5. **iPad/iPhone 放内容顶部**：移动端没有标题栏，tab 条单独占一条，在状态栏下面、浮动按钮上面。
6. **跨启动保留 tab**：`ReaderState.tabs` 存 id / 标题 / 路径 / 偏移与 `activeTabID`；
   返回/前进历史是会话内的，重启后不恢复。

## 实现

- `AppModel.Tab` 持有 `routes` / `routeOffsets` / `forward*`；当前 tab 的状态仍放在 `AppModel`
  的 `routes` 等字段里，`loadActiveTab` / `saveActiveTab` 在切换时搬运，视图层不用改。
- `ReaderState.TabSnapshot` 只存 path + offset；旧版本没有 `tabs` 时用 `reading.position` 生成一个 tab。
- `TabBar` 是两端共用的视图，都放在正文列/内容顶部，带底色和分隔线。
- 每次导航、切 tab、关 tab、页面加载和防抖后的滚动位置都会 `persistTabs()`。
- `Cmd+W` 用本地事件监听拦截：有多个 tab 时只关当前 tab，只剩一个时把事件交回系统关窗口。

## 后果

- 单窗口不再那么难受：对照两页用 tab，不必开两个窗口（[0052](0052-window-and-size.md) 的单窗口仍成立）。
- tab 多了横向滚动；没有拖动排序、tab 总览，"Cmd+点击在新 tab 打开"也还没做。
- 重启后每个 tab 的返回/前进历史会丢，只剩当前页——不把整条路由栈写进 UserDefaults。
- Mac 的 tab 条在正文列内，全屏时不会随窗口工具栏消失。

## 补记 · 2026-10-29：tab 条移出标题栏

第一版把 tab 条放在窗口工具栏里。实际看下来，它会从标题栏左端压过目录区域，视觉上不属于正文。

改为放在**正文列顶部**：标题栏下方、目录右侧，只占正文宽度；窗口变宽时跟着正文列变宽，
不再需要计算固定宽度。窗口工具栏恢复系统默认（不再用 unified toolbar），窗口标题也回来了。
`Cmd+T` / `Cmd+W` 不变。

## 补记 · 2026-11-03：Cmd+点击链接开新标签页

macOS 上按住设置里选定的修饰键（默认 Command）点正文、速查卡片里的链接，会新建一个标签页并直接打开目标页；
普通点击仍然在当前标签页跳转。新标签页的历史从目标页开始，不复制来源页的历史。

只在 macOS 生效：iOS 的点击/链接回调拿不到修饰键状态。iPad 以后可以补一个
「在新标签页打开」的链接菜单，不依赖外接键盘。

## 补记 · 2026-11-03：切 tab 后的滚动位置

切回一个 tab 时，`PageScreen` 会整页重建。ScrollView 初始布局会先把顶部 block 报上来，
这个 0 偏移会在恢复滚动之前把 `routeOffsets` 冲掉，表现就是"回到原 tab 文章在页首"。

只忽略初始 0 还不够：`ScrollView` 刚重建、正文还没显示时，`scrollTo` 也可能落空，
要等用户滚一下才把挂起的滚动位置补上。固定延时试过，仍会不稳定。

现在给目标 block 挂一个位置探针，`ReaderView` 滚动后测量它在视口里的 y，
确认真的到顶（±4pt）后才显示正文；没到就重试，最多 20 次。恢复期间 `topBlock`
不回报，正文保持隐藏。新建/关闭 tab 往返的滚动位置已用 UI 测试覆盖——不滑动也应回到原位置。
