# 内容管线：怎么验证，下游怎么用

对应决策：[0001/0002/0003/0004/0005](../decisions/)。本文只讲现状，不讲设想。

## 一、产物是什么

一次构建（`python3 Tools/content/run.py build --pack`，约 35 秒）产出四样东西：

| 产物 | 大小 | 身份 |
|---|---|---|
| `pack/source.tar.gz` | 28 MB | **原文**，逐字节，事实来源 |
| `pack/manifest.json` | 1.5 MB | 每个文件的 sha256 |
| `content.jsonl` | 56 MB | **阅读层**，每页一条 block 记录 |
| `pack/toc.json` | 761 KB | **目录树**，8544 个节点 |
| `pack/build-info.json` | 1 KB | 构建清单：上游 commit、解析器指纹、内容版本 |
| `report.md` / `baseline.json` | — | 验证报告与回归基线 |

阅读层是原文的**确定性函数**：丢掉它，随时能从原文重算出来。

## 二、验证分成六层

| 层 | 检查 | 机制 | 全量？ |
|---|---|---|---|
| 字节 | C8 | 归档取原文 → sha256 比对 → 重新解析 → block 哈希比对 | 是 |
| 文本 | C1 | 归一化空白后，源页可见文本与 block 文本逐字符相等 | 是 |
| 节点 | C2 | 每个 DOM 元素要么被规则处理，要么进透明容器，要么命中忽略白名单；白名单外的新标签报警 | 是 |
| 引用 | C3 | `id` 全部保留；内部链接全部可解析；断链与基线比只减不增 | 是 |
| 结构 | C4 / C5 | 每个 block 通过 schema；render 后再 parse 与原 block 一致 | 是 |
| 变更 | C6 | 上游没变的页，输出哈希不许变 | 是 |
| 目录 | C9 | 目录里每条链接都要落到真实页面；统计覆盖率 | 是 |
| 人工 | C7 | 40 页黄金样本人眼看 | 抽样 |

这里最关键的是 **C1**。它不关心内容对不对，只关心字有没有少、顺序有没有乱、有没有重复。实现过程中它抓到过四类静默丢内容的 bug（条件注释尾巴重复、嵌套表格行重复、孤儿行丢失、`UL` 套 `UL` 整段消失），每一类在预览里都不显眼。

**C8** 负责另一件事：证明阅读层不是手改出来的，而是原文的函数。少了这条，内容库就可能变成一个谁也不知道怎么来的文件。

**C6** 把"正确性"降级成"没变化"。上游没动过的页，输出一字节都不该变——这是确定性的，不需要标准答案。

## 三、"完整性"到底保证到哪一步

分四个维度看，前三个可以硬保证，第四个不能：

| 维度 | 能否保证 | 依据 |
|---|---|---|
| **字节完整** | 能 | C8：原文逐字节可取回，sha256 校验 |
| **文本完整** | 能 | C1：全量 7187 页逐字符比对，零失败 |
| **节点完整** | 能 | C2：白名单外的元素会报警，不会静默丢弃 |
| **结构正确** | 部分 | C4/C5 只证明"自洽"，不证明"符合阅读结构" |
| **语义正确** | 不能 | 机器无法判断一句话该是标题还是正文 |

第三行是这套体系的天花板。具体例子：7187 页里有 3614 页（50%）没有标题块，因为 Word 导出把小标题和正文塞进同一个 `<P>`，层级只由颜色和加粗表达。C1 看不见这种损失——字一个不少，层次没了。

这类问题只能靠人眼（C7）或视觉对照，不能靠不变量。

另外两条明确**不在**保证范围内：

- 上游自身的错。171 条断链、16 条扩展名不符、152 条断锚点，都是源文件里就断的，我们只基线化，不修（AGENTS.md 禁止改原文）。
- 像素级还原。class 与内联样式都保留了，但在浏览器里靠 CSS 级联算出来的效果，换到原生渲染器要重新翻译一遍。

## 四、下游怎么用

```
原文 tar.gz ──┬─→ 解析 ─→ content.jsonl ─┬─→ 渲染（阅读页）
             │                          ├─→ 导航（目录 / 页内标题）
             │                          ├─→ 搜索（全文索引）
             │                          ├─→ 实体（法术 / 怪物索引页）
             │                          └─→ 引用（交叉跳转表）
             └─→ 追新：diff 原文，只重解析变了的页
```

**渲染**：`blocks` 直接映射到原生视图——段落、标题、列表、表格、引用、分隔线；行内用 `b/i/u/s/sup/sub` 加 `c/sz/fa`。`faithful` 模式可以按原样式渲染（用于对照），`reading` 模式用自己的排版（用于阅读）。

**导航**：书级目录来自 `不全书.wcp` 的 `[TOPICS]` 段——8544 个节点、79 个顶层、7 层、483 个纯文件夹节点。树是 `{t: 标题, u: 页面路径, c: 子节点}`，紧凑键因为节点多。覆盖 7044/7187 页（98%），未覆盖的 143 页主要是第三方内容。页内层级另来自 `h1`–`h6`。

**搜索**：从 `blocks` 抽纯文本建 FTS。因为已经有 block 边界，搜索结果可以定位到段落级，而不是只给一个页码。

**引用**：C3 已经算出每条内部链接的实际落点（6390 条按语料根解析、352 条按文件目录），可以直接生成 `(页, 锚点) → (页, 锚点)` 的跳转表。

**实体**：法术已抽 1290 条，字段完整率 99.8%。可以直接做"按环阶/学派/职业筛选"的索引页。

**定位**：书签和阅读进度建议用 `(page, anchor)`，没有锚点时退到 `(page, block index)`。因为 C6 保证同一上游版本下 block 不变，索引在重建后仍然有效。

**追新**：原文层是 tar，可以直接与上一版 diff 出变更页；只重解析变更页，再跑 C6 —— 输出一定可解释。

## 五、还缺什么

| 缺口 | 影响 | 归属 |
|---|---|---|
| 存储格式没定 | JSONL 是交换格式，App 要 SQLite | D3 |
| 实体只做了法术 | 怪物/物品索引做不了 | 0001 第二批 |
| 增量包没做 | 更新只能整包替换 | D4 |
| 143 页不在目录里 | 第三方内容没有浏览入口，只能靠搜索命中 | D6 定范围时处理 |

## 六、内容版本与上游版本

`build-info.json` 里记三样东西，用来回答"这份内容是什么"：

| 字段 | 例子 | 用途 |
|---|---|---|
| `upstream.commit` | `81b587c51` · 1015之存一下 | 对应哪个上游快照 |
| `upstream.dirty` | `false` | 工作区有改动时置真，提醒"这份内容不对应任何 commit" |
| `parser.fingerprint` | `f45125799c5fb476` | 解析器源码哈希 |
| `content.version` | `29fe386867c5` | 由上面三项加页数、目录节点数派生 |

解析器指纹是三者里最容易被忽略的：内容变了，得能立刻分清是**上游改了**还是**我们改了**。前者要重跑并核对 C6，后者要跑回归。
